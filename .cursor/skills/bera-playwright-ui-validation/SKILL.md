# BERA Playwright UI Validation

## PURPOSE

Use Playwright for visual and functional validation of the BERA Reflex GUI.

Use this skill whenever implementing or reviewing:

- dashboard UI
- search setup UI
- completed-search results
- marketplace comparison tables
- responsive layout
- Alibaba / Facebook / Mercado Libre views
- visual regressions
- navigation behavior

## PLAYWRIGHT RULES

Use the installed Playwright browser tooling to validate the REAL rendered BERA UI.

Do not validate appearance only by reading source code.

For visual UI tasks:

1. launch/reuse Reflex
2. open the frontend in the browser
3. use viewport 1440x900 as the primary desktop reference
4. navigate using the real UI
5. click controls rather than mutating state directly when practical
6. capture screenshots
7. inspect visual hierarchy and alignment
8. perform at most two focused refinement passes

## PRIMARY VIEWPORTS

Validate:

1440x900
1280x800
1920x1080

Primary acceptance:

1440x900

## BERA VISUAL VALIDATION

Check:

- sidebar width and alignment
- header height
- search form proportions
- two-column search mode selector
- Alibaba / Facebook / Mercado Libre brand marks
- result limit selector
- primary CTA positioning
- marketplace summary cards
- comparison table alignment
- product thumbnails
- prices
- range strips
- stars/ratings where genuine
- opportunity gauge
- right-side search summary
- price distribution visualization
- Nueva búsqueda behavior
- complete / partial / error states

## REFERENCE-DRIVEN WORK

When the user supplies visual reference screenshots:

- open the BERA implementation at the same approximate viewport
- compare against the reference deliberately
- prioritize layout, proportions, density, typography and hierarchy
- do not declare PASS merely because the app renders

## ANTI-AI UI CHECK

Flag:

- excessive rounded cards
- unnecessary pills
- huge whitespace
- repeated AI-dashboard patterns
- inconsistent spacing
- generic icon blocks
- weak table hierarchy
- elements that look autogenerated rather than intentionally designed

## MARKETPLACE BRAND CHECK

Prominent instances of:

Alibaba
Facebook Marketplace
Mercado Libre

should normally include the corresponding marketplace brand treatment.

Do not fabricate logos.

## FUNCTIONAL VALIDATION

Test real UI behavior offline where possible:

- multi-market vs single-market mode
- result limit 1/3/5
- platform selection
- loading state
- complete state
- partial error state
- Nueva búsqueda reset
- history accordion
- navigation

## NO PROVIDER CALLS DURING UI VALIDATION

Unless explicitly instructed otherwise:

Apify = 0
Alibaba live requests = 0
Facebook live requests = 0
Mercado Libre live requests = 0
DeepL = 0
MiniMax = 0

Use fixtures/mocks/persisted safe state.

Do not read .env.

## SCREENSHOTS

For substantial UI work capture at minimum:

1. before search
2. completed search
3. comparison table
4. right-side results summary

Use descriptive screenshot names.

## FINAL VERDICT

Return:

PASS

or:

NEEDS REFINEMENT

If NEEDS REFINEMENT, list no more than 5 highest-value visual problems,
ordered by severity.

Do not redesign from scratch.
